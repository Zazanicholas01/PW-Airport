## `init_graph.py`

Read this file as the route recipe builder behind setup import. `setup_bus.py` does not invent paths itself. It feeds spline payloads into `InitGraph`, then asks it to compute the ordered segment lists that Unity can later follow.

## Graph State And Public Inputs

`InitGraph` is a long-lived accumulator. The main public inputs are:

- `add_master_spline(...)`
- `add_spline(...)`
- `build_paths()`

The setup handler depends on these entrypoints to transform Unity spline exports into a backend path model.

<TransportCodeBlock title="init_graph.py">
```python
class InitGraph:
    def __init__(self, airport_id: str = PERSONAL_AIRPORT):

        self.master_nodes = []
        self.master_edges = []
        self.master_spline = []
        self.splines = []
        self.airport_id = airport_id
        self.master_links = {}

    def add_splines(self, payload) -> None:
        """Add many splines from the given payload."""
        self.splines.extend(payload)

    def add_spline(self, spline) -> None:
        """Add a single spline payload."""
        self.splines.append(spline)

    def add_master_spline(self, spline) -> None:
        """Add the master spline payload."""
        self.master_spline = spline
        self.construct_master_links()
        self.extract_t_master_edges()
```

## Schema Dependency: Master Links

`InitGraph` depends on `schema_nodi.json` for the connectivity model. The file is not optional in practice because it tells the graph which stand splines are reachable from which master spline knot index.

The important translation is from schema link ids like `C3` into Unity-facing spline names like `Spline_C3`.

<TransportCodeBlock title="init_graph.py">
```python
def construct_master_links(self) -> None:
    """Construct a list of links between nodes and other splines"""

    schema_path = Path(__file__).resolve().parent.parent / NODE_SCHEMA_JSON_PATH
    try:
        with schema_path.open('r', encoding='utf-8') as f:
            links_schema = json.load(f)
    except FileNotFoundError as e:
        logger.warning("Schema file not found: %s", schema_path, exc_info=True)
        return
    except json.JSONDecodeError as e:
        logger.warning("Error decoding JSON schema: %s", schema_path, exc_info=True)
        return

    for i, node in enumerate(links_schema.get('nodes', [])):
        links = node.get('links', [])
        links = [f"Spline_{link}" for link in links]
        self.master_links[i] = links
```

## Unity Spline Dependency: Master Edge Extraction

The second major dependency is the Unity master spline payload itself. `extract_t_master_edges()` reads knot coordinates from the export and converts them into normalized edge slices.

Those `t_start` and `t_end` values are what later let the backend define a partial traversal over the single master spline instead of copying geometry.

<TransportCodeBlock title="init_graph.py">
```python
def extract_t_master_edges(self) -> None:
    """Extract the t parameters for master edges from the master spline."""

    knots = self.master_spline.get("knotEntries", [])
    if not knots or len(knots) < 2:
        return None, None
    try:
        x_coords = [knot.get("parameters", [])[0]["x"] for knot in knots]
    except (KeyError, IndexError, TypeError):
        return

    ms_length = x_coords[-1] - x_coords[0]
    if ms_length <= 0:
        return

    t_values = [(x - x_coords[0]) / ms_length for x in x_coords]

    for i, (t_start, t_end) in enumerate(zip(t_values, t_values[1:]), start=1):
        self.master_edges.append(
            {
                "name": f"MS_{i-1}{i}",
                "t_start": t_start,
                "t_end": t_end
            }
        )
```

## Landing Path Assembly

Landing paths are built as:

1. full landing spline
2. one sliced segment on the master spline
3. reversed stand spline

This is where `master_links`, `master_edges`, and the known landing or stand ids come together into the route recipe shape used later by the database layer.

<TransportCodeBlock title="init_graph.py">
```python
def build_paths(self) -> None:
    """Building Paths based on Master Edges, Master Links and Splines"""

    def find_master_edges(start_link, end_link):
        if end_link == len(self.master_edges):
            return self.master_edges[start_link:]
        return self.master_edges[start_link:end_link]

    available_stands = [f"Spline_{x}" for x in AVAILABLE_STANDS]
    available_landings = [f"Spline_{x}" for x in LANDING_SOURCES]

    paths = []
    start_link = 0
    for landing_spline in available_landings:
        for stand_spline in available_stands:
            end_link = None
            for n, link in self.master_links.items():
                if stand_spline in link:
                    end_link = int(n)
                    break

            if end_link is None:
                continue
```

## Departure Path Assembly And Published Output

Departure uses the same core ingredients but a different order:

1. stand spline forward
2. master spline slice toward the end
3. departure spline forward

At the end, `InitGraph` exposes a final combined `self.paths` list. That list is what `setup_bus.py` reads to build `models.Path(...)` rows.
