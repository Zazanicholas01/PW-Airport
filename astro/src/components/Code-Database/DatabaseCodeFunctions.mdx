## Session Factory Strategy

The first part of the file solves a practical problem: some callers want to inject a shared `Session` factory at startup, while scripts or isolated utilities want the module to work without extra wiring.

<TransportCodeBlock title="db_functions.py">
```python
_session_factory: sessionmaker | None = None

def configure_session_factory(Session: sessionmaker) -> None:
    """Inject the SQLAlchemy session factory (recommended at app startup)."""
    global _session_factory
    _session_factory = Session

@lru_cache()
def _fallback_session_factory() -> sessionmaker:
    return sessionmaker(bind=get_engine(), future=True)

def _get_session_factory() -> sessionmaker:
    return _session_factory or _fallback_session_factory()
```

## Sliding-Window Read Model

`list_flights_in_sliding_window(...)` is the read model that keeps showing up in higher layers. Its job is not to return one clean SQL state. Its job is to return the set of flights that the scheduling loop still cares about.

That is why it merges several queries:

- unscheduled outbound departures
- unscheduled inbound arrivals
- scheduled outbound departures with airplanes already assigned
- inbound flights still waiting to depart from the remote airport
- inbound flights already approaching the local airport

<TransportCodeBlock title="db_functions.py">
```python
def list_flights_in_sliding_window(*, airport_icao: str, now_utc: datetime, window: timedelta):
    """List all the flights inside the scheduling window"""

    now_utc = as_utc(now_utc)
    now_db = now_utc.astimezone(timezone.utc)
    upper = now_db + window

    with _get_session_factory()() as session:
        q = (
            select(models.Flight)
            .where(models.Flight.airplane_id.is_(None))
            .where(models.Flight.status == FLIGHT_STATUS.UNSCHEDULED)
            .where(
                or_(
                    and_(models.Flight.origin == airport_icao, models.Flight.departure_time <= upper),
                    and_(models.Flight.destination == airport_icao, models.Flight.arrival_time <= upper),
                    and_(models.Flight.destination == airport_icao, models.Flight.departure_time <= upper)
                )
            )
        )
```

## Outbound Assignment Flow

Outbound scheduling is split into two persistence steps:

1. pick and reserve a parked airplane already linked to a stand
2. assign a `Path` from that stand to `Departure`

<TransportCodeBlock title="db_functions.py">
```python
def assign_airplane_to_departure_flight(*, flight_id: str, required_type: str | None) -> tuple[str, str] | None:
    """Assign airplane to departure flight"""

    with _get_session_factory()() as session:
        flight = session.get(models.Flight, flight_id)
        if flight is None or flight.airplane_id is not None:
            return None

        q = (
            select(models.Airplane.id, models.Stand.id)
            .join(models.Stand, models.Stand.airplane_id == models.Airplane.id)
            .where(models.Airplane.status == AIRPLANE_STATUS.PARKED)
        )
```
</TransportCodeBlock>

def assign_path_to_airplane(*, airplane_id: str, source: str, destination: str) -> int | None:
    """Assign path to airplane"""

    with _get_session_factory()() as session:
        path_id = session.execute(
            select(models.Path.id)

## Inbound Preparation And Arrival Reservation

Inbound scheduling has a different shape:

- create a synthetic airplane row if the flight does not already have one
- mark the remote departure as started
- reserve an appropriate stand near arrival
- assign a landing path from the range-specific landing source to that stand
