## `dashboard_views.py`, `detail-page.html`, `detail-page.js`, and `detail-page.css`

Read this group as the detail-page subsystem. It is separate from the dashboard table shell, but it reuses the same snapshot ideas and the same clock feed.

## Server-Side HTML Rendering

<TransportCodeBlock title="dashboard_views.py">
```python
def render_detail_page_from_snapshot(snapshot: dict[str, object]) -> HTMLResponse:
    return render_detail_page(
        title=str(snapshot["title"]),
        subtitle=str(snapshot["subtitle"]),
        fields=list(snapshot["fields"]),
        image_url=str(snapshot["image_url"]),
        ...
    )
```
</TransportCodeBlock>

The field renderer optionally adds `data-field-key` attributes so later browser refreshes can patch values in place.

## Client Refresh Loop

<TransportCodeBlock title="detail-page.js">
```javascript
async function refreshDetail() {
  if (!apiPath) return;

  const response = await fetch(apiPath, {
    method: "GET",
    headers: { "Accept": "application/json" },
    cache: "no-store",
  });
```
</TransportCodeBlock>

The page also opens `/ws/clock`, projects simulated time locally, and updates the progress bar every 250ms between sync messages.
