## `status_constants.py`

Read this file as the shared domain vocabulary for the project. It is more than status labels. It also carries model metadata, airport-specific identifiers, timing defaults, websocket settings, and spline names that tie together transport, handlers, schedulers, and graph building.

## Airline, Flight, Stand, And Airplane Status Classes

The status classes are implemented as dataclasses used like static namespaces. They group related values and tuple sets that higher-level code uses for eligibility checks and transitions.

This is the vocabulary read directly by handlers and schedulers when deciding what state changes are valid.

<TransportCodeBlock title="status_constants.py">
```python
@dataclass
class AIRLINE_CATEGORIES:
    NATIONAL = "National"
    EUROPEAN = "European"
    INTERNATIONAL = "International"

    NATIONAL_CODE = "N"
    EUROPEAN_CODE = "EU"
    INTERNATIONAL_CODE = "I"
```
</TransportCodeBlock>

## Graph And Spline Vocabulary

The final section provides the identifiers that tie setup import and graph building together:

- schema path
- departure and landing spline names
- the master spline id used by InitGraph

These constants are the shared language between `setup_bus.py`, `init_graph.py`, and Unity-exported spline data.

<TransportCodeBlock title="status_constants.py">
```python
NODE_SCHEMA_JSON_PATH = "schema_nodi.json"

DEPARTURE_SPLINE = "Departure"
```
